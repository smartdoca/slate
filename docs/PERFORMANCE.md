# 千行协同文档性能（0.4.1，2026-09-13）

## 规范核对

已核对 `doca-collaboration` 和 `doca-editor-integration` 的完整契约。本次瓶颈来自包内重复投影、序列化和归一化，不需要 Doca 修改规范。批量操作仍产生一次本地 Yjs 内容事务；初始化、远端更新、选区和静置不产生本地提交。资源、权限、连接、持久化和 ACK 的所有权不变。

codec 仍为 `slate-kit`，schemaVersion 仍为 `3`；根 Map/Text 名称、命令编码、epochId 与 checkpoint 格式均未改变。缓存不写入文档，恢复仍使用原始 Yjs update，不能改用 JSON 重建。

## 改动

- 千行粘贴先收集结构命令，统一校验、提交并同步文本。去掉逐行调用完整 execute 路径造成的全文克隆、命令回放和差量编码；无效结构批次在写入前拒绝。
- 每个 Y.Text 只加入一次 UndoManager scope。已有文本读取不再反复构造千项 scope Set。
- 本地 Slate 修改提交后保留其不可变模型引用，跳过未变化节点的文本比较，不再把本地修改完整投影回自身。远端和撤销/重做继续正常投影；并发回复不能被本地去重过滤。
- 纯文本剪贴板批量归一化。表格/分列命令不再重复请求同一投影。
- 选区变化不重新生成目录；装饰函数、空装饰数组和块选中上下文保持稳定。宿主随选区刷新时不会因此迫使每个正文元素重新渲染。
- 大文档阈值改为跟随实际块数，因此空文档粘贴超过默认 300 块时也能启用已有的离屏渲染优化。
- 示例页仅在内容操作时序列化并保存，初始文档仅解析一次。此本地存储演示不是 Doca 协同保存方案。

## 测量与边界

使用本机 Node、Vitest 和 jsdom，1000 个普通中文段落及两个内存 Yjs 副本。耗时受同时运行的测试和机器负载影响，不作为固定 CI 时间阈值。

| 路径 | 修改前 | 修改后最终串行专项测量 |
| --- | --- | --- |
| 协同模型从 1 行粘贴至 1000 行 | 76,282 ms；因阻塞超过 60 秒导致基线测试超时 | 250 ms |
| 上述批次读取完整模型次数 | 999 次 | 1 次 |
| 千行模型中输入一个字符并转发远端 | 32 ms | 4.5 ms |
| 挂载编辑器，通过 Slate 纯文本剪贴板粘贴 1000 行 | 未记录可比较基线 | 1,060 ms，含 React/jsdom 提交 |
| 挂载编辑器，20 次选区更新，宿主每次均刷新 | 未记录可比较基线 | 124 ms；正文元素 render 回调 0 次；目录刷新 0 次；内容提交 0 次 |

这些不是浏览器绘制帧率或 Doca 生产端到端数据。没有宣称任意复杂表格、图示、十万行或任意数量评论均保持相同耗时。结构命令日志仍保留，未引入日志压缩、epoch 重建或完整 DOM 虚拟化；大范围原生文本选择仍可能触发浏览器布局工作。

全量 35 个测试文件、133 项测试通过。全量并行测试时模型粘贴约 754 ms、挂载粘贴约 1,823 ms，说明耗时受负载影响；最终表格数据采用 `yarn test:performance --no-file-parallelism`。真实静置脚本运行 60,008 ms，本地和远端内容提交均为 0，checkpoint 字节不变。类型检查、库构建和 Node ESM 入口检查通过。

## 可重复验证

```sh
yarn typecheck
yarn test
yarn test:performance
yarn build:lib
yarn test:node-esm
yarn test:collaboration-idle
```

- `src/collaborationPerformance.test.ts`：千行批次仅一次本地更新、远端零回声、后续输入不读取全文/重复扩展 scope、撤销重做、checkpoint 恢复、无效批次原子拒绝，以及本地发送时立即收到远端回复的连续输入。
- `src/largeDocument.test.tsx`：挂载编辑器的纯文本剪贴板、动态大文档阈值、宿主重渲染时的选区成本、目录零刷新、双副本一致、千行粘贴整体撤销重做。
- `scripts/verify-collaboration-idle.mjs`：使用构建后的公开 Yjs 入口，千行模型、100 次选区移动、真实等待 60 秒；校验本地/远端内容回调均为零，原始 checkpoint 字节不变。
- 原有协同、输入法、原子元素、评论锚点、同账号 presence 和只读回归继续运行。

## Doca 接入建议

现有 Skill 已要求以下行为，无需放宽规范：

1. 只订阅一次 `session.onLocalUpdate` 进入待确认队列。不要为弥补性能监听所有 `Y.Doc` update 或改变 ACK 语义。
2. `onChange` 仍可能由选区变化触发，以兼容宿主格式工具栏；不要在该回调中无条件执行全文 stringify、深拷贝、持久化或 setValue。`onOutlineChange` 现在只在初始化及内容变化时生成目录。
3. session、adapter、plugins 和初始值保持稳定；远端使用 applyRemoteUpdate，不通过受控 value 重置编辑器。
4. Doca 真实双页面的浏览器绘制、网络、持久队列及服务端 ACK 仍需宿主联合验收。内存双副本测试不等于外部服务验收。
