# 项目架构

本文说明当前实现，而不是未来能力承诺。消费方接入统一从 [README](../README.md) 开始；协同接入及上线边界见其中的 [Yjs 协同接入](../README.md#yjs-协同接入)。

## 包边界与分层

| 层 | 主要文件 | 职责 |
| --- | --- | --- |
| 公共入口 | `src/index.ts`、`headless.ts`、`yjs.ts`、`languages.ts` | React、纯数据、协同、字典四个消费入口 |
| 文档宿主 | `RichTextEditor.tsx` | Slate 生命周期、只读、插件、事件、协同绑定、ref |
| 命令/查询 | `api.ts`、`editor.ts`、`slateCommands.ts` | 上层控制接口、编辑规则、表格执行路由 |
| 查找替换 | `search.ts` | 模型枚举、版本化匹配、定位、单次/批量原生替换 |
| 结构/身份 | `types.ts`、`schema.ts`、`ids.ts` | schema 2、稳定 ID、加载准备、唯一性检查 |
| 表格模型 | `table.ts`、`tableCommands.ts`、`tableNormalization.ts` | ID 几何、命令 reducer、矩形投影、剪贴板 |
| 表格交互 | `components/TableBlock.tsx`、`tableNavigation.ts` | 鼠标选择、上下文操作、行列尺寸、视觉光标导航 |
| 内置呈现 | `components/ElementRenderer.tsx` 及其他组件 | 文本、代码、卡片、图示、浮层 |
| 资源/文案 | `resources.tsx`、`i18n.tsx`、`languageMessages.ts` | 运行时上传状态、地址解析、字典 |
| 协同 | `yjs.ts`、`yjsTransport.ts` | 文本 CRDT、结构命令、Slate 投影、同步握手 |
| 示例与基准 | `demo/`、`PERFORMANCE.md` | 业务外壳示例和历史性能测量 |

包仅渲染文档和内部交互浮层，不输出产品顶部导航或目录侧栏。目录返回数据，资源依赖业务回调，网络/服务端存储由业务提供。headless 不引入 UI/CSS，但不应将其理解为完全零 React 依赖的独立 npm 包；依赖边界以构建产物为准。

## 非协同数据流

业务 JSON 经 schema 准备后进入 Slate。普通文字操作由 Slate 执行；表格结构操作统一经过命令 reducer，再更新 Slate 树。onChange/getValue 输出当前值，业务决定保存时机。全量 setValue 会替换文档并清空本地历史，不是增量更新协议。

查找由 `search.ts` 枚举模型而非读取 DOM：文本块将相邻格式 leaf 映射为连续范围，代码块读取 `code` 字段，void 原子节点被排除。匹配绑定当前内容修订，任意本地或远端内容 operation 都会使旧匹配失效。单次替换使用原生 Slate transaction；批量替换按倒序执行并合并为一个撤销批次，因此会自然进入现有 onChange、协同 origin 和保存流程。搜索面板、结果高亮与快捷键属于宿主。

段落属性可组合：标题、列表、待办、引用、对齐与缩进不必互斥。代码和卡片使用独立字段维护文本；图示使用 X6 编辑并导出预览，不能假定所有 Block 都直接用同一种 children 文本字段。

## 表格模型

表格列保存在 columns，行保存在 children。单元格使用稳定 rowId/columnId 对应行列，拥有自己的内容 Block。merges 独立保存参与区域的行列 ID。rowspan、colspan 和隐藏格由投影计算，不作为存储真相。

结构命令对当前有效行列计算矩形结果。非协同 reducer 返回新表格或 null；单元格纯文字输入不运行全表结构规整。合并将内容移动到锚点，拆分只删除关系，不恢复副本。因此没有 placements 或专为撤销合并内容准备的历史副本。

UI 的 Path 只用于当前 Slate 树定位；持久化命令与跨端操作使用 ID。内容移动保持原 Block ID，复制则创建新 ID。

## 协同数据流

1. Y.Doc 保存初始元数据、结构命令和按文本 Block ID 关联的 Y.Text。
2. 前端文字变更由适配器转换到 Y.Text；结构变化通过共享 reducer 命令进入 Y.Doc。
3. 结构命令按 Lamport 时钟和命令 ID 确定性重放，生成一致的结构，再结合文本生成 Slate 投影。
4. Yjs update 经带 epoch/schema 校验的传输层进入串行 outbox；数据库提交后的精确 ACK 才清除队首，远端投影不回声发送。
5. 后端/Agent 可以运行相同 runtime 发起命令；也可只应用、保存、转发 update。

这不是纯 merges 集合 CRDT：当前保留结构命令历史，用统一顺序处理重叠合并、拆分和行列变更。投影合法性不等于所有用户意图都能被同时保留，指向删除目标的命令可能不生效。无需额外“修复版本”，但历史存储不是免费的。

表格冲突的具体规则：

- 独立增行、增列保留，按有效行列交叉生成格子；已删除列不留下可渲染的多余格。
- 新增穿过合并区域时扩展区域；重叠合并按统一顺序处理，后续操作覆盖重叠关系，投影不允许非矩形或重叠合并。
- 合并移动内容 Block 并保留其 ID，使并发文字编辑跟随内容；拆分仅解除合并关系。删除合并锚点而区域仍存活时，内容迁至存活锚点。
- 同步后乐观结果可能调整；结构重排后的撤销结果可能不同于单机。

同一房间初始化只能由一个授权流程完成。已有房间加载完整 Yjs 状态，而不是从 JSON 重建身份。多个进程可借助粘性路由或消息总线同步，但 Yjs 不替代鉴权、初始化互斥、可靠存储和持久化 ACK。当前 SDK outbox 仅在页面内存中，关闭页面前的未确认写入不具备离线持久保证。

## 资源与评论

图片/附件占位进入文档，文件对象、blob 预览、错误和进度只存在 React 运行时；成功写回稳定 path。预览和下载分别解析到业务地址。上传任务并未持久化为离线队列。

评论正文属于业务服务；SDK 为单个文本 Block 提供 Yjs 相对位置。保留 Yjs 身份才能持续解析锚点。跨 Block 评论、多段高亮、线程 UI 和权限均需上层实现。Awareness 为单独的临时在线数据，不进入文档持久化。

## 性能与当前限制

- 大文档渲染隔离不等同于完整虚拟滚动，初值解析、目录扫描及业务全量序列化仍有成本。
- 协同结构日志存在增长与重放成本，尚无安全在线历史压缩接口。
- 原始 path 操作不能直接广播；远端选择和恢复不能依赖过期 path。
- 自定义复杂字段、流程图整体属性的并发语义需要单独验证；不能把文字级 Y.Text 保证推广到所有内部对象。
- 当前有并发增删、合并拆分、文本、撤销和传输测试；真实多端 IME、长离线、大规模长日志仍是上线验证项。

具体测试文件在 `src/*.test.ts`；历史测量见 [性能报告](../PERFORMANCE.md)。修改公共接口时应同步更新 README、导出类型和 package-api 测试，避免实现和消费示例漂移。
